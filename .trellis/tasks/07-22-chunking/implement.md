# Implementation plan: chunking (indexing module)

## Ordered checklist

1. **Transcriber fix** — **Done**. `transcription/transcriber.py:161-187` captures `language` from the pre-align result and merges it back in.
2. **Config** — **Done**. `config.py:53-70`: `chunk_min_duration_seconds=20.0`, `chunk_max_duration_seconds=360.0`, `audio_tier` dict (`Short`/`Medium`/`Long`, single `max_episode_duration_seconds` boundary per tier, first-match-wins lookup order). See design.md's "Token threshold tiers" section for the pinned numbers/rationale.
3. **Migration** — **Done**. `0004_indexing_fields.py`: `IndexStatus` enum + `episode.index_status`, `episode.language`, `chunk.search_vector` (generated TSVECTOR + GIN index). `models/episode.py`/`models/chunk.py` updated to match.
4. **Worker update** — **Done**. `transcription/worker.py:130` sets `episode.language = result.get("language")` alongside `transcript_data`/`transcript_status`.
5. **Cleaning — external dependency, not this task's implementation, but this task owns the call site** — `clean_words`/`join_words` themselves are **Done** (owned by the separate, already-archived `07-28-filler-word-cleaning` task). This task consumes `clean_words(segments, language=None)` / `join_words(words, language=None)` — `clean_words` called once per episode by the worker (step 10), on the whole `segments` list, *before* `chunker.build_chunks(...)`; `join_words` used inside `SizeBasedChunker`'s oversized-segment pre-pass (step 7), to rebuild the text of a synthetic segment. **Revised 2026-08-12 (user)**: cleaning is no longer called per-chunk by the embedder (step 8) — see step 8's note.
6. **Tokenizer loading**: implement `indexing/tokenizer.py`, `get_tokenizer() -> Tokenizer` — `huggingface_hub.hf_hub_download(repo_id="BAAI/bge-m3", filename="tokenizer.json", cache_dir=Path(settings.data_dir) / "hf_cache", revision=<pinned_sha>)` then `tokenizers.Tokenizer.from_file(path)`. Plain loader, no internal caching — called exactly once, by `Chunker.py::create_chunker()` at worker startup (mirroring `LocalWhisperX.__init__`'s eager-load-once precedent). See design.md's `tokenizer.py` section.
7. **Chunking interface + Phase 1 implementation** — see design.md's "`indexing/` module layout" section for the full file-by-file design. One file per chunking strategy, all returning the same `list[ChunkSpan]` shape:
   - `indexing/BaseChunkerInterface.py` — `ChunkingError`, `ChunkSpan{text, start, end, segments}`, `Chunker` Protocol (`build_chunks(segments, *, min_tokens, max_tokens, desired_tokens, min_duration, max_duration, language=None) -> list[ChunkSpan]`).
   - `indexing/SizeBasedChunker.py` — Phase 1 concrete class, `__init__(self, tokenizer)` holds the loaded tokenizer as instance state (not a per-call arg). Operates on **already-cleaned** segments — the worker (step 10) calls `clean_words` on the whole transcript before passing `segments` in; `ChunkSpan.text` is the concatenation of included segments' own (cleaned) `text` fields (never rebuilt from any word list). `ChunkSpan.segments` carries the cleaned segment-shaped dicts spanned (**not** a flattened word list — needed for word-level timestamps); each piece produced by the oversized-segment pre-pass wraps its word sub-span in a single synthetic segment dict. Closing gate is two-part: **3a** hard bounds (OR on max — either `max_duration` or `max_tokens` triggers a close attempt; AND on min — both `min_duration` and `min_tokens` must clear before a close is allowed); **3b** within that legal zone, the greedy nearest-token-target rule (one-step lookahead comparing `|desired_tokens - current|` vs. `|desired_tokens - current_plus_next|`, tokens only, not duration). Token counts computed once per segment, summed into a running total (O(n), no re-tokenizing the growing buffer). Oversized segments are handled by a **pre-pass** (`_split_long_segments`, calling `_split_segment` / `_cut_index`) that runs before the accumulation loop and returns a new plain segment list, so the loop has no special case and the pieces stay eligible to merge with their neighbours — **revised 2026-08-21 (user)**, previously an in-loop fallback emitting finished `ChunkSpan`s; see design.md's "Oversized-segment pre-pass" section for the two problems that motivated the change. Trigger stays **duration-only**, no token check; pieces are `ceil(duration / max_duration)` equal shares (not greedy max-width windows), each cut snapped to nearby sentence-final punctuation and the cut set deduplicated rather than window-constrained. Unit tests against a synthetic multi-segment transcript: both hard bounds respected, nearest-target rule picks the closer-to-`desired_tokens` boundary over always-extend-to-max, contiguity holds (flattening every chunk's `segments` back into words reconstructs the original sequence), `ChunkSpan.text` matches raw segment text exactly (not word-rebuilt). Pre-pass tests: equal shares rather than a max-width remainder (the 361s-against-360s case), punctuation snapping, collision dedupe on sparse words, words with no timestamps at all, an over-long segment with fewer than two words emitted whole, and CJK text rebuilt without injected spaces.
   - `indexing/SimilarityBiasedChunker.py` — Phase 2 slot, skeleton implementing `Chunker`, `build_chunks` raises `NotImplementedError`. Not blocking Phase 1; see design.md for the deferred design.
   - `indexing/Chunker.py` — `create_chunker(strategy: str = "size_based") -> Chunker` factory. The only file importing both concrete classes; loads the tokenizer once and constructs `SizeBasedChunker`.

   **Note**: `indexing/chunker.py` (singular, no interface split) already exists on disk with a stale pre-2026-07-29 implementation (duration-only bounds, `ChunkSpan.words` instead of `.segments`, no tokenizer/token counting). This step replaces it with the multi-file structure above — delete the old file once the new one is verified, and rewrite `tests/test_chunker.py` accordingly (it currently tests the old shape).
8. **Embedder**: implement `indexing/embedder.py` (`embed_batch`, `EmbeddingError`) using `httpx.AsyncClient` against `settings.embedding_*`. **Revised 2026-08-12 (user)**: the caller (worker, step 10) just passes `[chunk.text for chunk in chunks]` directly — no per-chunk `clean_words`/`join_words` call, since cleaning already ran once on the whole transcript before chunking (step 10 runs `clean_words` before `chunker.build_chunks`). `embed_batch` itself just takes plain strings. Smoke-test with a real DeepInfra call (small input) to confirm request/response shape before wiring into the worker.
9. **Store**: implement `indexing/store.py` (`replace_chunks`) — writes `chunk.text` from `ChunkSpan.text` (cleaned), `chunk.start`/`chunk.end` from `ChunkSpan.start`/`.end` (already word-level-derived by the chunker — step 7 — never recomputed here), and `chunk.embedding` from the embedder's output (computed directly from `chunk.text`). `search_vector` is DB-generated, so no app code needs to populate it.
10. **Worker**: implement `indexing/worker.py` (`reset_stale_processing`, `poll_ready`, `claim_episode`, `resolve_token_tier`, `index_episode`, `run_worker`), modeled on `transcription/worker.py`. Build the `Chunker` once via `Chunker.py::create_chunker()` at worker startup (this is what loads the tokenizer — step 6 — internally). `index_episode` calls `clean_words(segments, episode.language)` once on the whole transcript **before** `chunker.build_chunks(...)` (**revised 2026-08-12, user** — previously cleaning ran per-chunk, after chunking, inside the embedder). `resolve_token_tier` picks `(min_tokens, max_tokens, desired_tokens)` from the episode's total duration (`segments[-1]["end"] - segments[0]["start"]`) via `settings.audio_tier` (first-match-wins, `Short → Medium → Long`).
11. **CLI**: implement `indexing/cli.py`, modeled on `transcription/cli.py`. Calls `create_chunker()` + `run_worker(...)`. No `[extra]`-guarded import needed (no optional heavy deps here).
12. **End-to-end validation**: run the indexing worker against already-transcribed episodes; verify chunk rows via the acceptance criteria in `prd.md`, including `episode.language` populated (for episodes transcribed since the transcriber fix) and `search_vector` populated (`SELECT search_vector FROM chunk LIMIT 1`). First indexing-worker run needs network access to download BGE-M3's `tokenizer.json` (step 6) — confirm it's cached (no repeat download) on a second run.

## Review gates

- Before step 7 (chunker): step 2's tier numbers and widened `chunk_max_duration_seconds` are now pinned `[assumption]` defaults (see prd.md's real-data grounding via `tokenizer_playground.py`), not derived from actual short-news/long-form audio — worth a last look before building on them, since they're a reasoned extrapolation, not a measured fact, for two of the three tiers.
- After step 3 (migration): confirm `alembic upgrade head` + `downgrade -1` + `upgrade head` round-trips cleanly before building on top of it.
- After step 6 (tokenizer loading): confirm `hf_hub_download` succeeds once (network reachable to huggingface.co) and a second call hits the local cache with no re-download, before building the chunker on top of it.
- After step 8 (embedder): confirm one real DeepInfra call succeeds and returns 1024-dim vectors before wiring into the worker loop — cheaper to catch API-shape mismatches in isolation.
- After step 12: manual audio spot-check against acceptance criteria before marking the task done.

## Rollback points

- Migration `0004` has a `downgrade()` — safe to revert independently of code changes.
- The transcriber.py fix and worker.py's extra `episode.language` assignment are small, isolated diffs — easy to revert without touching the rest of the transcription code path.
- Each new module (`indexing/*`) is additive; no existing module is modified beyond the fix above, so reverting is "delete the new files + revert the transcriber fix + revert the migration." `cleaning/*` is out of scope for this task entirely (owned by `07-28-filler-word-cleaning`), so there's nothing of this task's own to roll back there.
